# AI MONEY START — GUIDE
## MODULE 3 — 3-DAY SKILL SPRINT (черновик, близкий к финальному)

Формат: **BOOTCAMP**, не курс. Короткие объяснения, много действий, чёткие DONE WHEN-гейты, результат каждый день. Общая структура WHAT/WHY/HOW/EXAMPLE/TEMPLATE/YOUR TURN/DONE WHEN сохранена, но внутри HOW — плотная последовательность из 14 секций; объяснения не повторяются в каждом из 5 треков Section 8, там даётся только то, что отличается.

**Важная привязка к плану:** в Module 2 был День 1 (выбор услуги). Skill Sprint — это **Дни 2–4** общей 30-дневной системы. Ниже секции 5–7 так и озаглавлены: День 2 / День 3 / День 4.

---

## WHAT

Ты уже выбрал(а) PRIMARY SERVICE в Module 2. Следующие 3 дня — не про мастерство. Это про переход из «я вообще не знаю, как это делается» в «я понимаю стандарт результата, могу повторить базовый процесс и способен(на) сделать первый концептуальный кейс».

**3-Day Skill Sprint не делает тебя экспертом.** Никаких «стань специалистом за 3 дня» или «освой профессию за выходные» — это неправда, и продукт так не обещает.

## WHY

Главная ошибка новичка: 20 часов YouTube → ещё один курс → ещё 100 сохранённых материалов → ни одного результата. Контент про обучение потребляется бесконечно, потому что после него не требуется ничего создавать.

Здесь — наоборот: **LEARN ENOUGH TO BUILD**, не LEARN EVERYTHING BEFORE YOU BUILD. Цикл на 3 дня:

```
SEE  →  BREAK DOWN  →  REBUILD  →  CREATE  →  REVIEW
```

Увидеть хороший пример → разобрать его → повторить механику → создать свою версию → проверить качество.

## HOW

### SECTION 1 — MINIMUM SELLABLE SKILL

**EXPERT LEVEL** — это годы опыта, широкий scope, способность решать нестандартные задачи.
**MINIMUM SELLABLE SKILL** — это «я могу выполнить ограниченный и чётко описанный scope без обмана клиента и без обещаний того, чего пока не умею».

После 3 дней у тебя не будет права называть себя экспертом. Будет право честно продавать узкий, конкретный результат.

| TOO BROAD | SAFE STARTER SCOPE |
|---|---|
| «Я разработчик любых сайтов» | «Я могу собрать простой одностраничный сайт по утверждённой структуре» |
| «Я маркетолог» | «Я могу подготовить контент-пак для Telegram по согласованным темам» |
| «Я дизайнер презентаций» | «Я могу собрать презентацию на 8–12 слайдов по готовой структуре» |
| «Я копирайтер» | «Я могу написать лид-магнит на 5–10 страниц по согласованной теме» |
| «Я специалист по видео» | «Я могу написать 10 сценариев Reels по проверенной формуле хука» |
| «Я настрою вам маркетинг» | «Я могу переписать 10–15 карточек товара под структуру площадки» |
| «Я эксперт по автоматизациям» | «Я могу настроить один простой сценарий автоответа на частые вопросы» |
| «Я сделаю вам продвижение» | «Я могу провести короткий цифровой аудит сайта/соцсети по чек-листу» |

### SECTION 2 — ПРАВИЛО 70/20/10

> Это практическая модель обучения внутри AI MONEY START, а не научно доказанное универсальное распределение.

```
70%  —  создание руками
20%  —  разбор хороших работ
10%  —  теория
```

Если сегодня доступно 3 часа: ориентир — около 2 часов на создание, 35–40 минут на анализ референсов, остальное на теорию. Это не секундомер, а направление внимания: **практика важнее бесконечного потребления контента.**

### SECTION 3 — QUALITY REFERENCE SYSTEM

«Найди референсы» — не инструкция, а отговорка. Вот система: для выбранной услуги найти 10–15 хороших примеров и на каждый заполнить карточку.

**REFERENCE ANALYSIS CARD**

```
Источник:                          [ ]
WHAT WORKS (что реально работает):  [ ]
STRUCTURE (из чего состоит):        [ ]
VISUAL / WRITING PATTERN:           [ ]
CTA / BUSINESS PURPOSE:             [ ]
WHAT I WOULD COPY AS A PRINCIPLE:   [ ]
WHAT I WOULD NOT COPY DIRECTLY:     [ ]
```

Ключевое различие:

- **REFERENCE** — понять принцип (структуру, логику, тип решения).
- **COPY** — воспроизвести чужое конкретное решение (текст, композицию, бренд-элементы).

Продукт учит первому. Второе — плагиат, а не навык.

Где искать: YouTube, Google, Pinterest, Behance, Dribbble, реальные сайты, соцсети, портфолио специалистов, публичные кейсы, ChatGPT, Claude.

**Оговорка про AI:** ИИ может помогать объяснять, почему решение работает, но сам по себе не является доказательством того, что решение хорошее. Сверяй объяснение AI с реальными качественными примерами, а не наоборот.

### SECTION 4 — DECONSTRUCTION METHOD

Новичку проще научиться, если перестать видеть «красивый сайт» и начать видеть **Hero → Offer → Proof → CTA.**

Разбор результата на части по услугам:

```
LANDING PAGE:     Hero · Offer · Proof · Services · Benefits · Process · FAQ · CTA
PRESENTATION:      Cover · Problem · Insight · Solution · Proof · Offer · CTA
TELEGRAM CONTENT:  Hook · Context · Value · Example · CTA
```

Универсальная форма разбора для любого deliverable:

```
INPUT      —  что было дано на входе (бриф, тема, данные)
STRUCTURE  —  из каких блоков состоит результат, в каком порядке
DECISIONS  —  какие решения принял автор и почему (тон, акценты, что убрал)
OUTPUT     —  что в итоге получает зритель/клиент
```

### SECTION 5 — ДЕНЬ 2 ПЛАНА: SEE + DECONSTRUCT

**Цель:** понять стандарт качества выбранной услуги.

```
1. Найти 10 сильных примеров
2. Выбрать лучшие 3
3. Разобрать их по Reference Analysis Card
4. Выписать повторяющиеся паттерны
5. Создать свой QUALITY CHECKLIST услуги
```

Не нужно смотреть 50 видео — 10 примеров достаточно. QUALITY CHECKLIST — это список из 5–8 пунктов «что обязательно должно быть в моей работе», собранный из повторяющихся паттернов 3 разобранных референсов.

### SECTION 6 — ДЕНЬ 3 ПЛАНА: REBUILD

**Цель:** не создать оригинальный проект с нуля, а сначала повторить механику хорошего результата.

**Границы авторского права — обязательны:**

| НЕ копировать | Можно взять |
|---|---|
| логотип, бренд | принцип |
| точный дизайн | структуру |
| тексты | тип решения |
| иллюстрации | логику |
| целые композиции | композиционный подход |

Пример: не копировать конкретную презентацию Apple — понять «один тезис на экран, визуальная иерархия, много пространства, короткие доказательства», и применить это к своей теме.

**REBUILD CHECKLIST**

```
☐ Я взял(а) структуру/принцип, а не текст и не визуал целиком
☐ Тема/ниша в моём rebuild — другая, не оригинальная
☐ Я могу объяснить, что именно я повторил(а) и зачем
☐ Я не выдаю этот rebuild за собственный оригинальный проект
```

Rebuild **не идёт в портфолио** — это тренировка, а не демонстрационный кейс.

### SECTION 7 — ДЕНЬ 4 ПЛАНА: CREATE

Теперь — условный бриф и собственный результат:

```
Brief → Research → Outline → First Draft → AI Critique → Human Review → Revision → Final
```

**AI CRITIQUE нельзя принимать автоматически.** Цикл:

```
ASK AI  →  CHECK AGAINST REFERENCES  →  DECIDE YOURSELF
```

ИИ способен галлюцинировать, выдумывать «правила», перехваливать работу и не замечать бизнес-контекст. Финальное решение всегда принимает человек, сверяясь с реальными референсами из Section 3 — не с мнением модели о себе самой.

### SECTION 8 — 5 SERVICE-SPECIFIC SPRINTS

Для TOP 5 Starter Services из Module 2 — отдельный маршрут на Дни 2–4. Общая логика (SEE→REBUILD→CREATE, границы копирования, AI-критика) не повторяется — см. Sections 5–7. Здесь только то, что отличается по услуге.

**TRACK A — LANDING PAGES**

- **День 2 (Learn):** структура лендинга — Hero, Offer, CTA, social proof, Services, Benefits, Process, FAQ, основы responsive, визуальная иерархия. Не уходить в программирование глубже необходимого. Если используешь AI-конструктор/no-code — важно различать «AI сгенерировал код» и «сайт действительно работает»: минимальная проверка — mobile, links, buttons, forms, overflow, loading, читаемость текста.
- **День 3 (Rebuild):** разобрать хороший лендинг, повторить принципы на другом вымышленном бизнесе.
- **День 4 (Create):** собрать простой landing concept.
- **Landing Quality Checklist:** заголовок понятен за 3 секунды · есть один явный CTA · есть социальное доказательство или его заглушка · сайт открывается и читается на телефоне · нет битых ссылок/кнопок-заглушек без пояснения.

**TRACK B — COMMERCIAL PRESENTATIONS**

- Минимум: storyline, один слайд = одна идея, иерархия, заголовок, подтверждающие данные, визуальная согласованность, CTA.
- **День 2:** разбор 3 сильных презентаций.
- **День 3:** rebuild 5–7 слайдов.
- **День 4:** собственная презентация на 8–12 слайдов.
- **Presentation Quality Checklist:** каждый слайд читается за 5 секунд · нет слайдов с двумя разными мыслями · есть чёткий CTA в конце · визуальный стиль одинаков на всех слайдах.

**TRACK C — LEAD MAGNETS / PDF GUIDES**

- Минимум: аудитория, проблема, обещание, структура подачи информации, применимость на практике, визуальная иерархия, CTA.
- **День 2:** разбор 5 качественных материалов.
- **День 3:** rebuild структуры.
- **День 4:** собственный мини-гайд. Не 50 страниц — достаточно законченного короткого продукта (5–10 страниц).
- **PDF Quality Checklist:** есть конкретное обещание в заголовке · каждый раздел даёт применимое действие, не только теорию · есть CTA в конце · оформление единообразно.

**TRACK D — TELEGRAM CONTENT PACKS**

- Минимум: аудитория, content pillars, hooks, форматы, тон, CTA, календарь.
- **День 2:** разбор 5–10 сильных каналов/постов.
- **День 3:** тренировочные 5 постов.
- **День 4:** готовый sample pack — 10 постов + контент-календарь.
- Запрещены придуманные результаты («увеличит продажи на 40%»).
- **Content Pack Quality Checklist:** у каждого поста есть цель (продать/прогреть/вовлечь) · есть разнообразие форматов, не только текст · есть CTA хотя бы в трети постов · календарь показывает логику, а не случайный порядок.

**TRACK E — SHORT-FORM VIDEO SCRIPTS**

- Минимум: Hook, Retention, Payoff, CTA, Pacing, визуальные указания.
- **День 2:** разбор минимум 15 роликов в нише — не просто смотреть, а заполнять по каждому: Hook, первые 3 секунды, Structure, Retention device, Payoff, CTA.
- **День 3:** rebuild механики 5 сценариев без копирования текста.
- **День 4:** 10 оригинальных сценариев под одного условного клиента.
- **Script Quality Checklist:** хук цепляет за первые 3 секунды · есть один чёткий payoff · CTA простой и один · есть пометки по визуалу/монтажу, а не только текст.

### SECTION 10 — AI AS A TUTOR

Не «научи меня дизайну» — конкретные workflows с плейсхолдерами.

**1. EXPLAIN A CONCEPT**
```
Объясни, что такое [ПОНЯТИЕ] в контексте [УСЛУГА], простыми словами,
как для человека без опыта. Приведи 1 короткий пример. Не используй
профессиональный жаргон без объяснения.
```

**2. REFERENCE BREAKDOWN**
```
Вот описание/материалы примера: [ВСТАВИТЬ ОПИСАНИЕ ИЛИ ССЫЛКУ].
Разбери его структуру по блокам, объясни назначение каждого блока,
найди закономерности. Задай мне уточняющие вопросы, если данных
не хватает. Не придумывай детали, которых нет в материале.
```

**3. SKILL GAP FINDER**
```
Я делаю [УСЛУГА] для [НИША]. Вот что я уже понимаю: [СПИСОК].
Каких 5 конкретных навыков/знаний мне не хватает для базового
качественного результата? Отвечай списком, без общих фраз.
```

**4. PRACTICE BRIEF GENERATOR**
```
Сгенерируй условный бриф для тренировочного проекта: услуга — [УСЛУГА],
ниша клиента — [НИША], цель клиента — [ЦЕЛЬ]. Формат брифа: проблема,
целевая аудитория, ключевое сообщение, ограничения.
```

**5. CRITIQUE MY DRAFT**
```
Вот мой черновик: [ВСТАВИТЬ РАБОТУ]. Мой Quality Checklist: [СПИСОК].
Оцени черновик строго по каждому пункту чек-листа. Не хвали то,
что не в чек-листе. Укажи максимум 3 главные проблемы.
```

**6. COMPARE AGAINST CHECKLIST**
```
Вот мой Quality Checklist: [СПИСОК]. Вот моя работа: [РАБОТА].
Пройдись по каждому пункту чек-листа и ответь только "выполнено"
или "не выполнено" — без общих комментариев.
```

**7. EXPLAIN MY MISTAKES**
```
Вот моя работа: [РАБОТА]. Вот референс, на который я ориентировался:
[РЕФЕРЕНС]. В чём конкретно моя работа слабее референса по структуре
и логике решений — не по вкусу, а по чек-листу [СПИСОК].
```

**8. CREATE NEXT PRACTICE EXERCISE**
```
Я только что изучил(а) [ТЕМА/БЛОК]. Дай мне одно конкретное
тренировочное задание, которое займёт не больше [ВРЕМЯ], и после
которого у меня будет готовый артефакт, а не просто понимание темы.
```

### SECTION 11 — THE ANTI-TUTORIAL LOOP

Симптом: «мне кажется, я ещё недостаточно готов» → ещё один тьюториал → ещё один → ещё один.

**Правило: ONE INPUT → ONE OUTPUT.** После каждого обучающего материала — обязательное действие.

```
посмотрел(а) видео про Hero          →  создай 3 Hero-секции
прочитал(а) про hooks                 →  напиши 10 hooks
изучил(а) структуру презентации       →  создай outline на 8 слайдов
```

Если output нет — обучение не считается завершённым, сколько бы материалов ни было просмотрено.

### SECTION 12 — QUALITY GATE

Перед переходом в Portfolio Module (Module 5) проверь:

```
☐ Можно ли показать работу человеку без объяснения «я новичок»?
☐ Понятно ли, что это за deliverable?
☐ Нет ли очевидных ошибок?
☐ Работает ли результат технически?
☐ Решает ли он поставленную задачу?
☐ Могу ли я объяснить каждое главное решение?
☐ Проверил(а) ли я работу на нескольких референсах?
☐ Исправил(а) ли я самые очевидные замечания?
☐ Не использовал(а) ли я выдуманные данные?
☐ Не скопировал(а) ли я чужую работу?
```

### SECTION 13 — KNOW YOUR LIMITS

Узкий scope повышает безопасность и качество. Умение сказать «этого я пока не умею» — часть навыка, не его отсутствие.

```
Делаешь сайты       →  не продавай сложный backend, если не понимаешь его
Пишешь тексты        →  не обещай юридически корректный текст без специалиста
Настраиваешь автоматизации  →  не внедряй критичные для бизнеса процессы без нужной компетенции
Работаешь с медициной / финансами / правом  →  не выдавай AI-сгенерированный совет за профессиональную экспертизу
```
