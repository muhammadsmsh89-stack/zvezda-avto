# AI MONEY START — GUIDE
## MODULE 8 — SALES ENGINE (черновик, близкий к финальному)

**Формат:** часть PDF-продукта, не отдельный курс по продажам. Ориентир Guide-части — 7–9 плотных PDF-страниц. Полные библиотеки (Objection Library на 15 категорий, closing/prepayment scripts, 5 complete sales flows) — в `08a-module-8-sales-scripts.md`.

**Привязка к плану:** с Дня 9+, параллельно outreach. Когда лид отвечает «Интересно» / «Сколько стоит?» / «Давайте обсудим» — Module 8 превращает это в понятный sales process.

---

## WHAT

Discovery без допроса → summary → предложение конкретного scope → спокойное озвучивание цены → работа с реальным возражением → закрытие с понятным next step → предоплата → старт проекта. Именно в этом порядке, без пропусков.

## WHY

Новичок обычно либо сразу называет случайную цену, либо пишет огромный текст, либо соглашается на всё и делает бесплатно, либо боится назвать цену, либо теряет клиента после «я подумаю». **Продажа — не давление.** Это выяснение: есть ли реальная задача, можем ли мы её решить, совпадают ли ожидания, подходит ли scope, готов ли клиент платить. Иногда правильный итог диалога — **NOT A FIT**, и это нормальный результат, не провал.

```
CORE SALES FLOW:
INTEREST → DISCOVERY → FIT → SOLUTION → SCOPE → PRICE →
OBJECTIONS → AGREEMENT → PREPAYMENT → PROJECT START
```

## HOW

### SECTION 1 — DON'T PITCH TOO EARLY

Клиент: «Интересно». Новичок в ответ — огромное описание услуги + цена + пакеты + портфолио + условия + «когда начинаем?». Вместо этого — сначала контекст:

```
«Да, конечно. Чтобы предложить нормальный вариант, уточню пару вещей:
какую задачу хотите решить и что используете сейчас?»
```

### SECTION 2 — DISCOVERY WITHOUT INTERROGATION

```
ASK → LISTEN → CLARIFY → SUMMARIZE
```

Не анкета из 15 вопросов одним сообщением. Области (не все обязательны для каждого проекта): CURRENT STATE · DESIRED STATE · PROBLEM · SCOPE · TIMING · DECISION (кто согласовывает) · CONSTRAINTS · BUDGET CONTEXT (какой формат рассматривают).

### SECTION 3 — 10 GOOD DISCOVERY QUESTIONS

| Вопрос | WHAT IT REVEALS |
|---|---|
| «Что хотите получить в итоге?» | desired state |
| «Что используете сейчас?» | current state |
| «Что в текущем варианте не устраивает?» | problem |
| «Есть ли примеры, которые вам нравятся?» | style/reference |
| «Какие элементы обязательно должны войти?» | scope |
| «К какому сроку желательно закончить?» | timing |
| «Кто будет согласовывать итоговый вариант?» | decision maker |
| «Материалы уже есть или их ещё нужно собрать?» | constraints/inputs |
| «Есть ли технические ограничения?» | constraints |
| «Рассматриваете базовый вариант или более полную реализацию?» | budget context |

### SECTION 4 — DISCOVERY BY CHAT VS VOICE VS CALL

```
CHAT   — простой проект, понятный scope, клиент предпочитает переписку → 1–2 вопроса за сообщение
VOICE  — когда идею быстрее объяснить голосом, чем длинным текстом → коротко и структурированно
CALL   — сложный scope, несколько участников, дорогой проект, нужно быстро уточнить много вещей
```

Звонок не гарантированно повышает продажи — это просто более подходящий канал для сложных случаев.

### SECTION 5 — MINI SALES CALL (10–20 минут)

```
1. CONTEXT   — «Расскажите коротко, что хотите сделать»
2. CURRENT STATE — что сейчас
3. GOAL      — что хотят получить
4. DETAILS   — scope / материалы / сроки
5. SUMMARY   — «Правильно понял, что вам нужно…»
6. SOLUTION  — предложить подходящий формат
7. PRICE     — стоимость
8. NEXT STEP — что происходит дальше
```

### SECTION 6 — SUMMARIZE BEFORE SELLING

```
«Правильно понял: сейчас у вас [CURRENT]. Нужно [DESIRED].
Главное — [PRIORITY]. По сроку ориентируемся на [TIME].
Тогда я бы предложил [SOLUTION].»
```

Показывает, что слушал(а); помогает исправить недопонимание; делает предложение логичным. Ещё 4 примера по Top 5 — Scripts T1.

### SECTION 7 — QUALIFICATION: FIT CHECK

```
NEED           — есть реальная задача?
FIT            — моя услуга действительно подходит?
SCOPE          — я способен(на) выполнить?
TIMING         — срок реалистичен?
PAYMENT        — есть готовность обсуждать оплату?
COMMUNICATION  — можно нормально договориться?
```

Несколько критичных «нет» → не пытаться любой ценой закрыть сделку.

### SECTION 8 — HOW TO PRESENT THE SOLUTION

```
YOU SAID → SO I RECOMMEND → IT INCLUDES
```

```
ПЛОХО:  «Я ещё умею логотипы, сайты, дизайн, презентации, AI…»
ХОРОШО: «Для вашей задачи я бы предложил(а) лендинг на 7–8 смысловых
         блоков: первый экран, направления, преимущества, примеры
         работ, процесс и форма заявки.»
```

Предлагать только то, что связано с discovery. Ещё 4 примера по Top 5 — Scripts T2.

### SECTION 9 — HOW TO SAY THE PRICE

Price Builder уже в Module 5 — здесь только про произнесение цены.

```
PRICE + SCOPE + TERMS

Не: «20 тысяч»
А:  «По этому объёму стоимость — 20 000 ₽. В неё входит [scope],
     срок [X], два раунда правок. Стартуем после 50% предоплаты.»
```

После цены — не оправдываться, не писать сразу «но могу дешевле», не заваливать пятью пояснениями. Ещё 6 вариантов — Scripts T3.

### SECTION 10 — SILENCE AFTER PRICE

После цены клиент может молчать, читать, сравнивать, думать — это нормально.

```
STATE → CLARIFY IF NEEDED → LET THEM PROCESS
```

Не «могу сделать скидку» / «что думаете?» / «дорого?» сразу же — дать паузу, для переписки и звонка одинаково.

### SECTION 11 — OBJECTION ≠ REJECTION

«Дорого» может значить: нет бюджета · не понял ценность · сравнивает · не доверяет · scope слишком большой · хочет поторговаться · плохой timing. «Подумаю» может значить: реально нужно подумать · есть другой участник решения · нет срочности · неудобно отказать · остался вопрос. Не читать мысли клиента — уточнять.

### SECTION 12 — OBJECTION FRAMEWORK

```
ACKNOWLEDGE → CLARIFY → RESPOND → NEXT STEP
```

```
Client: «Дорого»
ACKNOWLEDGE: «Понимаю»
CLARIFY:     «Подскажите, стоимость выше ожидаемого бюджета или
              кажется большой относительно объёма?»
RESPOND:     в зависимости от ответа
NEXT STEP:   изменить scope / оставить предложение / закрыть цикл
```

Полная **Objection Library** на 15 типичных возражений (дорого, подумаю, нет бюджета, есть знакомый/студент, сделайте сначала, тестовое, почему дорого, нужна скидка, пришлите КП, обсудить с партнёром, слишком долго, нужно срочно, мы сами можем, вернёмся позже, гарантии результата) — каждая с WHAT IT MAY MEAN / BAD RESPONSE / 3 GOOD RESPONSES — в **Scripts T4**.

### SECTION 13 — DISCOUNT RULES

```
IF PRICE GOES DOWN → SCOPE SHOULD OFTEN GO DOWN TOO
```

```
CORE = 25 000 ₽. Клиент: «Есть 18 000 ₽».
Не: CORE за 18.
Можно: предложить STARTER scope.
```

Скидка допустима по реальной причине (repeat client · bundle · уменьшенный scope · гибкий дедлайн · другой разумный commercial reason) — не из искусственно придуманного повода.

### SECTION 14 — NEGOTIATION WITHOUT PANIC

```
1. Не отвечать мгновенной скидкой
2. Сначала понять причину
3. Менять scope, а не только price
4. Не обещать то, чего не умеешь
5. Быть готовым отказаться

GOOD FIT > ANY CLIENT
```

### SECTION 15 — PACKAGE SELLING

STARTER/CORE/PLUS из Module 5 — не отправлять все три всегда. Если задача очевидна — рекомендовать один: «По вашей задаче я бы выбрал(а) CORE, потому что вам нужна полноценная мобильная версия и подготовка структуры.» Пакеты — варианты, не инструмент запутывания.

### SECTION 16 — CLOSING

```
AGREEMENT → SUMMARY → PAYMENT → START DATE
```

```
«Тогда фиксируем: landing из 7 блоков, адаптив, два раунда правок,
срок 7 рабочих дней, стоимость 25 000 ₽. Если всё верно, отправляю
краткое подтверждение условий и реквизиты на 50% предоплаты.»
```

Не «Ну что, покупаете?» — нужен понятный next step. Ещё 6 closing scripts — Scripts T5.

### SECTION 17 — CONFIRM THE SCOPE IN WRITING

Перед оплатой/стартом — письменная фиксация, не «ну вроде договорились». **PROJECT SUMMARY TEMPLATE:**

```
Project:                [ ]
Deliverables:           [ ]
Deadline:               [ ]
Price:                  [ ]
Payment terms:          [ ]
Revisions:              [ ]
Not Included:           [ ]
Client materials:       [ ]
Final delivery:         [ ]
```

Не сложный юридический документ — просто письменная договорённость вместо устной.

### SECTION 18 — PAYMENT & LEGAL REALITY

AI MONEY START используется людьми из разных стран и возрастов — **нет одной схемы договора/оплаты, подходящей всем.** Пользователь сам соблюдает: законы своей страны, налоговые требования, правила платёжного сервиса, возрастные ограничения, требования к договорам/согласию законного представителя, если применимо.

Если пользователь несовершеннолетний — ему нужно отдельно проверить, какие сделки, способы получения оплаты и договоры он вправе заключать самостоятельно в своей юрисдикции, и требуется ли участие родителя/законного представителя. **Это не юридическая консультация.**

### SECTION 19 — PREPAYMENT

50/50 введено в Module 5 — здесь про спокойный запрос:

```
«Чтобы зафиксировать старт — отправляю реквизиты на 50%
предоплаты, [X] ₽. Вторая половина — после сдачи работы.»
```

Не «Переводите деньги» — профессиональная формулировка. Ещё 4 варианта (после созвона, в переписке, repeat client, milestone-проект) — Scripts T6.

### SECTION 20 — DO NOT START BEFORE THIS

```
☐ Scope confirmed
☐ Price confirmed
☐ Deadline confirmed
☐ Revisions confirmed
☐ Payment terms confirmed
☐ Required client materials understood
☐ Prepayment / согласованный первый milestone получен, где применимо
```

Только после этого — PROJECT START.

### SECTION 21 — WHAT IF CLIENT DISAPPEARS BEFORE PAYMENT?

```
Follow-Up #1 → Follow-Up #2 → Close Loop
```

Не гоняться бесконечно. Нет оплаты/подтверждения → не резервировать время, не начинать проект.

### SECTION 22 — SALES PIPELINE

Используется существующий Lead Tracker (Module 6), не новая система:

```
REPLIED → INTERESTED → DISCOVERY → OFFER SENT → WON / LOST / FOLLOW-UP
```

Каждый активный лид имеет NEXT ACTION + DATE. Пустой Next Action = сделка зависла.

### SECTION 23 — SALES SCOREBOARD

Используется Dashboard из Module 6–7, не новая система. Теперь важны: Positive Replies · Discovery Conversations · Offers Sent · Won · Revenue (только если пользователь сам хочет добавить).

| Симптом | Проверить |
|---|---|
| Много «интересно» → мало discovery | next step friction? слишком большой ask? |
| Discovery → мало офферов | плохой fit? неясный scope? страх назвать цену? |
| Офферы → мало побед | доверие? цена? timing? scope? слабая презентация решения? |

Универсальных «хороших процентов» здесь нет.

### SECTION 24 — 5 COMPLETE SALES FLOWS

Полные mini-dialogues (Initial Interest → Discovery → Summary → Offer → Price → одно возражение → Close) по всем Top 5 услугам — реалистичные, без искусственно удобного клиента — **Scripts T8.**

### SECTION 25 — "GUARANTEE RESULTS"

```
гарантировать DELIVERABLE / PROCESS, не sales / leads / views / revenue
```

```
«Я могу отвечать за согласованный scope, техническую работоспособность
страницы и выполнение проекта в рамках утверждённых требований.
Количество продаж зависит также от трафика, предложения, цены и
работы с заявками.»
```

Варианты по Top 5 — Scripts T7.

### SECTION 26 — SALES ETHICS

Не: придумывать кейсы · врать о загруженности · придумывать других клиентов · использовать fake scarcity · обещать гарантированный доход · скрывать ограничения · давить страхом · выдавать AI-output за профессиональную экспертизу · соглашаться на задачу выше компетенции. **Продажа должна повышать ясность, а не снижать её.**

# QUALITY CHECK

**1. Может ли абсолютный новичок провести нормальный sales dialogue?**
Да — Sections 1–8 дают линейную последовательность от «интересно» до предложения решения, с формулами на каждом шаге.

**2. Не превращён ли sales в манипуляцию?**
Нет — Section 26 (Sales Ethics) явно запрещает fake scarcity, придуманные кейсы, давление страхом; Section 11–14 требуют уточнять, а не додумывать за клиента.

**3. Есть ли понятный discovery process?**
Да — ASK→LISTEN→CLARIFY→SUMMARIZE (Section 2), 10 вопросов с WHAT IT REVEALS (Section 3), три режима chat/voice/call (Section 4).

**4. Умеет ли пользователь назвать цену?**
Да — Section 9, формула PRICE+SCOPE+TERMS с примером, плюс 6 дополнительных вариантов в Scripts T3.

**5. Есть ли конкретная работа с «дорого»?**
Да — Section 12 (framework) + отдельная детальная категория в Objection Library (Scripts T4).

**6. Есть ли «подумаю»?**
Да — Section 11 (что может значить) + отдельная категория в Objection Library.

**7. Есть ли «есть знакомый / дешевле»?**
Да — отдельная категория в Objection Library (Scripts T4).

**8. Есть ли «сначала сделайте»?**
Да — отдельная категория в Objection Library, с чётким разграничением portfolio/bounded sample vs полный проект без предоплаты.

**9. Есть ли test-task boundary?**
Да — в Objection Library («сделайте тестовое») зафиксирована граница bounded sample vs полноценный проект под видом теста.

**10. Понимает ли пользователь scope vs discount?**
Да — Section 13 (Discount Rules): IF PRICE GOES DOWN → SCOPE SHOULD OFTEN GO DOWN TOO.

**11. Есть ли closing?**
Да — Section 16, формула AGREEMENT→SUMMARY→PAYMENT→START DATE с примером, плюс 6 вариантов в Scripts T5.

**12. Есть ли prepayment?**
Да — Section 19, с примером и 4 доп. вариантами в Scripts T6.

**13. Есть ли письменная фиксация условий?**
Да — Section 17, Project Summary Template по 9 полям.

**14. Нет ли универсальных юридических утверждений?**
Нет — Section 18 прямо говорит «нет одной схемы, подходящей всем» и явно исключает юридическую консультацию.

**15. Учтены ли возрастные / юрисдикционные различия?**
Да — Section 18 отдельно адресует несовершеннолетних пользователей и необходимость проверки местных правил.

**16. Не гарантируем ли бизнес-результат?**
Нет — Section 25 прямо разводит DELIVERABLE/PROCESS (гарантируется) и sales/leads/revenue (не гарантируется).

**17. Не дублируется ли Module 5?**
Нет — Module 5 создавал Price Builder и пакеты; Module 8 учит их произносить и защищать в диалоге, не пересчитывает цену заново.

**18. Продолжает ли использоваться существующий Lead Tracker?**
Да — Section 22 прямо говорит «используется существующий Lead Tracker, не новая система».

**19. Готов ли пользователь после Module 8 получить первую оплату?**
Да — DONE WHEN заканчивается NEXT ACTION по каждой активной сделке и пониманием payment terms/prepayment — прямой мост к первой реальной сделке.

**20. Укладывается ли основная Guide-часть примерно в 7–9 PDF-страниц?**
Да — 26 секций даны как система с формулами и по 1 примеру, все объёмные библиотеки (15-категорийный Objection Library, closing/prepayment scripts, 5 полных диалогов) вынесены в `08a-module-8-sales-scripts.md`.
