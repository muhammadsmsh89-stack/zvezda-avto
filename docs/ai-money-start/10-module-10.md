# AI MONEY START — GUIDE
## MODULE 10 — REVIEW → REFERRAL → NEXT CLIENT (черновик, близкий к финальному)

**Формат:** финальный основной модуль. Ориентир Guide-части — 4–6 плотных PDF-страниц. Полные библиотеки сообщений — в `10a-module-10-growth-templates.md`. После этого модуля новые основные модули не создаются.

**Привязка к плану:** после каждого завершённого проекта, весь оставшийся месяц.

---

## WHAT

```
PROJECT COMPLETE → REVIEW → REAL CASE → REFERRAL → UPSELL/REPEAT →
BETTER PORTFOLIO → BETTER OFFER → NEXT CLIENT
```

**ONE CLIENT SHOULD CREATE MORE THAN ONE ASSET.** Не обязательно нового клиента — но после каждого проекта должна оставаться новая ценность для системы: Real Case, Review, Referral, Repeat Work, Upsell, доказательство цены, лучший offer, больше уверенности в продажах.

## WHY

Типичная ошибка новичка: получить деньги, закончить проект и больше никогда не использовать этого клиента как источник роста — «спасибо, всё отправил», и конец. Это не факт, что каждый клиент даст рекомендацию или повторную работу — Module 10 создаёт **систему возможностей**, не гарантию.

---

## HOW

### SECTION 1 — PROJECT CLOSEOUT

После handoff — не молчание, а короткий цикл: подтверждение передачи → проверка, что клиент всё получил → короткое напоминание про support → запрос feedback → позже review/referral/next step. Не отправлять всё разом одним перегруженным сообщением.

### SECTION 2 — ASK FOR FEEDBACK FIRST

До публичного отзыва — узнать, доволен ли клиент вообще:

```
«Подскажите, всё ли в итоге устроило по проекту? Если есть что-то,
что стоит учесть на будущее, буду благодарен(на) за обратную связь.»
```

Помогает не просить отзыв у недовольного клиента и выявить проблему заранее. Ещё 4 варианта — Templates T1.

### SECTION 3 — HOW TO ASK FOR A REVIEW

```
CONTEXT → WHY → EASY ACTION
```

```
«Спасибо за работу. Если результат вас устроил, буду благодарен(на)
за короткий отзыв в 2–3 предложениях: какая была задача и как вам
прошла работа. Это поможет мне показывать будущим клиентам реальный
опыт.»
```

Не «Оставьте отзыв пожалуйста!!!». Ещё 4 варианта (casual/professional/repeat client/после позитивного фидбека) — Templates T2.

### SECTION 4 — MAKE REVIEW EASY

Клиент может быть доволен, но не знать, что написать — не писать отзыв за него, дать вопросы для структуры:

```
1. Какая была задача?
2. Что было важно?
3. Как прошла коммуникация?
4. Что понравилось в результате?
5. Порекомендовали бы работу другим?
```

Ответ должен быть словами клиента.

### SECTION 5 — NEVER FAKE SOCIAL PROOF

Строго запрещено: выдумывать отзыв · писать отзыв от имени клиента · менять смысл слов клиента · добавлять результаты, которых клиент не говорил · использовать логотип без понимания, можно ли это делать · представлять concept project как оплаченный. Если клиент разрешил использовать отзыв/работу — фиксировать это.

### SECTION 6 — REAL CASE BUILDER

```
CLIENT / BUSINESS:      [ ]
PROJECT:                [ ]
INITIAL TASK:           [ ]
CONSTRAINTS:            [ ]
DELIVERABLE:            [ ]
MY APPROACH:            [ ]
KEY DECISIONS:          [ ]
PROJECT OUTCOME:        [ ]
CLIENT FEEDBACK:        [ ]
PERMISSION TO SHOW:     [ ]
```

BUSINESS RESULT можно добавлять, только если он реально измерялся, информация подтверждена и есть право её публиковать. Иначе — PROJECT OUTCOME: «Запущен адаптивный лендинг из 8 секций», не «Продажи выросли».

### SECTION 7 — CONCEPT → REAL PORTFOLIO

Не обязательно удалять все concept-кейсы сразу — постепенный переход: 3 Concept → 2 Concept + 1 Real → 1 Concept + 2 Real → 3+ Real Cases. Качество и релевантность важнее количества — не собирать 30 слабых кейсов.

### SECTION 8 — ASK FOR PERMISSION

Перед публикацией — понять, можно ли показывать бренд, дизайн, внутренние материалы, цифры, отзыв, название компании:

```
«Можно ли добавить эту работу в портфолио и указать название компании?
Если какие-то материалы или данные показывать нельзя — скажите,
я их исключу.»
```

Никаких универсальных юридических утверждений — только явный вопрос и явное согласие.

### SECTION 9 — REFERRALS

```
CONTEXT → WHO I HELP → LOW-PRESSURE ASK
```

```
«Если среди знакомых будет бизнес, которому тоже актуален
лендинг/обновление сайта, буду благодарен(на) за знакомство.»
```

Не «Дайте мне клиента». Ещё 6 вариантов под разные ситуации — Templates T3.

### SECTION 10 — THE INTRODUCTION MESSAGE

Если клиент согласился познакомить — не заставлять его придумывать текст самому, дать готовый forwardable intro:

```
«Могу познакомить вас с [ИМЯ]. Он(а) занимается [SERVICE] для
[CLIENT TYPE]. Мы недавно работали над [PROJECT], всё прошло хорошо.
Дальше можете обсудить напрямую.»
```

Не заставлять клиента писать ложную похвалу. Ещё 2 варианта — Templates T4.

### SECTION 11 — REFERRAL TRACKING

В существующий Lead Tracker — два поля: `REFERRED BY` и `REFERRAL GIVEN TO`. Новая CRM не создаётся — важно только знать, откуда появился клиент.

### SECTION 12 — NATURAL UPSELL MAP

Upsell ≠ продать ненужное. Upsell = заметить логичный следующий deliverable:

| Первый проект | Логичный следующий шаг |
|---|---|
| Landing Page | доп. страница под новое направление |
| Commercial Presentation | обновление deck под нового партнёра |
| Lead Magnet / PDF | лендинг / email-цепочка вокруг того же гайда |
| Telegram Content | ежемесячный контент-пак на постоянной основе |
| Short-Form Scripts | следующий месячный пакет сценариев |

### SECTION 13 — WHEN TO UPSELL

Не раньше, чем клиент получил первую работу. Лучшие моменты: клиент доволен · новая потребность возникла естественно · пользователь заметил связанную задачу · текущий проект завершён · клиент сам спрашивает про следующий шаг. Не придумывать проблему ради продажи.

### SECTION 14 — UPSELL SCRIPT

```
OBSERVATION → RELEVANCE → OPTION
```

```
«Теперь, когда лендинг готов, у вас остаётся отдельная страница под
[направление]. Если решите запускать его активнее, можно будет
собрать вторую страницу в том же стиле.»
```

Не «Вам срочно нужно купить ещё». Варианты под все Top 5 — Templates T5.

### SECTION 15 — REPEAT BUSINESS & CHECK-INS

```
30-DAY / 60-DAY CHECK-IN — практическая модель, не обязательный точный интервал
```

После разумного времени — проверить, всё ли работает, появились ли новые задачи, нужно ли обновление. Не «Ну что, ещё что-нибудь купить хотите?». 5 примеров check-in сообщений — Templates T6.

### SECTION 16 — RETAINERS

Подходит не всем услугам. **RETAINER FIT CHECK:**

```
☐ Есть ли регулярно повторяющаяся задача?
☐ Нужен ли результат каждый месяц?
☐ Могу ли я стабильно выполнять?
☐ Понимает ли клиент ongoing value?
```

Если нет — не предлагать retainer. Не превращать любую разовую услугу в подписку насильно.

### SECTION 17 — AFTER-PROJECT REVIEW

После проекта обновляются Portfolio, Offer, Sales Script, Price Evidence, FAQ, Process:

```
WHAT WENT WELL?                 [ ]
WHAT TO FIX?                    [ ]
WHAT TO STANDARDIZE?            [ ]
WHAT TO ADD TO PORTFOLIO?       [ ]
WHAT DID CLIENT VALUE MOST?     [ ]
WHAT TO CHANGE IN OFFER?        [ ]
WHAT TO CHANGE IN DELIVERY?     [ ]
```

### SECTION 18 — ASK WHY THEY BOUGHT

```
«Что в итоге стало главным фактором, почему вы решили работать
именно со мной?»
```

Помогает понять настоящий selling point (portfolio, цена, скорость, конкретное сообщение, понимание ниши, коммуникация) — не предполагать заранее. Ещё 2 варианта — Templates T7.

### SECTION 19 — PRICE REVIEW (после реального проекта)

Price Review Checkpoint из Module 5 применяется здесь на реальных данных, не «получил одного клиента → сразу ×2»:

```
☐ Стал ли результат сильнее?
☐ Появился ли real proof?
☐ Понял ли пользователь scope лучше?
☐ Был ли текущий price слишком низким?
☐ Сколько реально занял проект?
☐ Были ли непредвиденные задачи?
☐ Какую ценность клиент видел?
```

Итог: **KEEP PRICE** или **ADJUST PRICE.**

### SECTION 20 — PROJECT REVIEW (не только revenue)

Проект за 30 000 ₽ может быть хуже проекта за 20 000 ₽, если съел втрое больше времени:

```
PRICE:                            [ ]
TIME SPENT:                       [ ]
EXTRA SCOPE:                      [ ]
REVISION ROUNDS:                  [ ]
STRESS / COMPLEXITY:              [ ]
WOULD I TAKE THIS PROJECT AGAIN?  [ ]
```

Не сложные unit economics — просто понимание качества клиента/scope.

### SECTION 21 — CLIENT QUALITY SCORE

```
Clear Communication · Pays as Agreed · Respects Scope · Provides Materials ·
Reasonable Feedback · Good Service Fit · Repeat Potential · Referral Potential
```

Шкала 0–2 по каждому пункту — внутренняя модель пользователя, не объективная оценка человека, не для унижения клиентов.

### SECTION 22 — SPECIALIZATION FROM DATA

3 стоматологии + хорошие отклики + понятный процесс + нормальная цена → постепенный переход от «делаю сайты» к «делаю лендинги для стоматологий». **SPECIALIZATION CHECK:**

```
☐ Выполнено несколько похожих проектов?
☐ Понимаю нишу лучше, чем раньше?
☐ Легко ли находить лидов в ней?
☐ Ценят ли клиенты эту услугу?
☐ Можно ли выстроить повторяемый процесс?
```

Не специализироваться из-за одного случайного клиента.

### SECTION 23 — DON'T STOP OUTREACH AFTER ONE CLIENT

```
DELIVERY + LIGHT OUTREACH
```

Получил первый заказ → перестал искать клиентов → сдал проект → воронка пустая — типичная ошибка. Объём outreach может снижаться во время production, но pipeline не должен полностью останавливаться, если пользователь способен совмещать — и не до выгорания.

### SECTION 24 — THE NEXT CLIENT LOOP

Финальная схема Guide:

```
1. Close project
2. Ask feedback
3. Ask review
4. Build real case
5. Ask referral
6. Offer relevant next step
7. Update portfolio
8. Review price
9. Continue outreach
```

### SECTION 25 — FROM FIRST CLIENT TO SYSTEM

**FIRST CLIENT** — событие. **CLIENT ACQUISITION SYSTEM** — повторяемый процесс. У пользователя уже есть Offer, Portfolio, Lead System, Outreach, Sales, Delivery, Referral Loop — задача не искать новый «секрет заработка», а улучшать слабое звено текущей системы.

### SECTION 26 — FINAL FUNNEL DIAGNOSIS

| Симптом | Диагностическое направление |
|---|---|
| Нет лидов | ICP / sourcing |
| Лиды есть, нет ответов | качество лидов / outreach |
| Ответы есть, нет интереса | offer / fit |
| Интерес есть, нет продаж | sales / доверие / цена / timing |
| Продажи есть, плохая сдача | scope / production |
| Проекты завершены, нет повторов | fit / клиентский опыт / offer |
| Хорошие клиенты, низкий доход | цена / scope / объём / эффективность |

Это направления диагностики, не единственная гарантированная причина.

### SECTION 27 — 30-DAY FINISH LINE

К Дню 30 смотреть не на «заработал/не заработал», а на controllable metrics: Service Selected · Portfolio Cases · Leads Found · Messages Sent · Follow-Ups · Replies · Positive Replies · Discovery · Offers · Won · Projects Completed · Reviews · Referrals. Не обещание клиента за 30 дней — результат: работающая система и реальные рыночные данные.

### SECTION 29 — WHAT TO DO IF ZERO CLIENTS

Не «ты просто плохо старался» — диагностика:

```
☐ Было ли достаточно реальных действий?
☐ Были ли лиды подходящими?
☐ Был ли offer конкретным?
☐ Понятно ли portfolio?
☐ Были ли сообщения персонализированными?
☐ Были ли follow-ups?
☐ Были ли positive replies?
☐ Где ломается funnel?
☐ Не слишком ли сложная первая услуга?
☐ Есть ли реальные причины изменить стратегию?
```

**DO NOT RESET EVERYTHING.** Сначала изменить одно слабое звено (лиды, сообщение, оффер или портфолио) — затем тестировать снова.

### SECTION 30 — IF FIRST CLIENT WON

Система не закончена после одного клиента: **FIRST CLIENT → NEXT 3.** Задача — закончить хорошо, получить proof, продолжить pipeline, использовать новые данные, улучшить pricing. Конкретное число следующих клиентов не гарантируется.

☐ У меня есть Lead System

☐ Я умею проводить Discovery
☐ Я умею назвать цену
☐ Я умею фиксировать Scope
☐ Я понимаю Payment Terms

☐ Я умею провести Handoff

**1. Замыкает ли Module 10 всю систему?** Да — Section 24 (Next Client Loop) и Section 31 (Final Client Checkpoint) сводят все 10 модулей в один финальный цикл/чек-лист.

**2. Есть ли нормальный запрос feedback?** Да — Section 2, формула + 4 доп. варианта в Templates T1.

**3. Есть ли Review System?** Да — Sections 3–4, формула CONTEXT→WHY→EASY ACTION + Review Prompt из 5 вопросов.

**4. Не создаём ли fake reviews?** Нет — Section 5 прямо запрещает выдумывать/переписывать отзывы и представлять concept как оплаченный проект.

**5. Есть ли Real Case Builder?** Да — Section 6, 10 полей, с явным разграничением PROJECT OUTCOME vs непроверенный BUSINESS RESULT.
