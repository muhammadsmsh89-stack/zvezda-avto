# AI MONEY START — GUIDE
## MODULE 4 — 3-CASE PORTFOLIO SPRINT (черновик, близкий к финальному)

Формат: **BUILD PROOF**, не «сделай три красивые работы». Каркас WHAT/WHY/HOW/EXAMPLE/TEMPLATE/YOUR TURN/DONE WHEN сохранён; внутри HOW — 19 плотных секций.

**Привязка к плану:** это **Дни 5–7**. После Module 3 у пользователя уже есть навык минимального уровня, пройденный Quality Gate и понимание границ компетенции — Module 4 не переучивает, а превращает навык в 3 законченных доказательства.

---

## WHAT

За 3 дня — три законченных **Concept Project**, которые честно показывают: «я могу выполнить эту услугу» — потенциальному клиенту, а не самому себе.

К концу Дня 7 обязаны существовать:

```
1. 3 законченных Concept Projects
2. Каждый проект решает разную задачу
3. Каждый кейс оформлен понятно для клиента
4. Есть Portfolio Cover / Intro
5. Есть одна простая ссылка, чтобы отправить работы
6. Пользователь может рассказать о каждом кейсе за 30 секунд
7. Нигде не создаётся впечатление, что concept project был реальным оплаченным заказом
```

## WHY

Клиент редко оценивает портфолио как дизайнер или как коллега по цеху. Он думает проще: **«Этот человек сможет сделать что-то подобное для меня?»** Портфолио — не витрина красоты, а инструмент, который снижает его неопределённость.

Поэтому портфолио должно доказывать три конкретные вещи:

```
1. Я могу выполнить эту услугу
2. Я понимаю задачи бизнеса
3. Я умею доводить работу до законченного deliverable
```

Не «три красивые работы» — **BUILD PROOF**.

---

## HOW

### SECTION 1 — PORTFOLIO WITHOUT CLIENTS

Концептуальные проекты допустимы — но только если честно обозначены.

**Разрешённые формулировки:** Concept Project · Demo Project · Practice Case · Концептуальный проект · Демонстрационный проект.

**Запрещённые формулировки** (если этого не было на самом деле):

```
«Клиент обратился ко мне…»
«Мы увеличили конверсию…»
«Результат: +37% заявок»
«Компания выбрала мою концепцию…»
```

| REAL WORK | CONCEPT WORK |
|---|---|
| реальный клиент | самостоятельно выбранная компания/ниша |
| реальный бриф | самостоятельно сформулированная задача |
| реальные ограничения | демонстрационное решение |
| реальный результат | никаких выдуманных бизнес-результатов |

Оба типа могут показывать качество работы. **Смешивать их нельзя** — это единственное жёсткое правило раздела.

### SECTION 2 — THREE CASE STRATEGY

```
CASE 1 — CORE          →  самая типичная задача услуги → «я умею базовый коммерческий deliverable»
CASE 2 — DIFFERENT PROBLEM →  та же услуга, другая бизнес-задача → «я умею адаптироваться под контекст»
CASE 3 — PREMIUM / AMBITIOUS →  чуть сильнее/сложнее/выразительнее → «вот куда растёт качество моей работы»
```

**Ограничение на CASE 3:** он не должен выходить далеко за реальную компетенцию из Module 3. Не заставляй себя делать сложный проект, который не способен(на) нормально закончить — незаконченный CASE 3 хуже, чем более простой, но завершённый.

### SECTION 3 — CASE BRIEF GENERATOR

```
SERVICE:                            [ ]
BUSINESS TYPE:                      [ ]
BUSINESS NAME:                      [ ]
REAL OR FICTIONAL BUSINESS:         [ ]
TARGET AUDIENCE:                    [ ]
WHAT THE BUSINESS SELLS:            [ ]
MAIN PROBLEM:                       [ ]
PROJECT GOAL:                       [ ]
DELIVERABLE:                        [ ]
KEY INFORMATION:                    [ ]
CONSTRAINTS:                        [ ]
DESIRED STYLE / TONE:               [ ]
CALL TO ACTION:                     [ ]
DEADLINE FOR THIS PRACTICE CASE:    [ ]
WHAT I WANT THIS CASE TO PROVE:     [ ]
```

Если за основу взят реальный существующий бизнес без его участия — **нельзя** писать, будто компания заказала работу. Обязательная пометка: *«Неофициальный концепт. Компания не является заказчиком проекта.»* Использовать только публичные данные либо полностью вымышленный (fictional) бриф — никакой конфиденциальной информации.

```
Business

поля как [PLACEHOLDER], не выдумывай их. Никогда не придумывай:
выручку, количество клиентов, результаты, награды, число лет работы,
кейсы, проценты, цены, технические характеристики. Если факт не дан

```

### SECTION 5 — CASE DIVERSITY MATRIX

| | CASE 1 | CASE 2 | CASE 3 |
|---|---|---|---|
| Niche | | | |
| Audience | | | |
| Problem | | | |
| Deliverable | | | |
| Style | | | |

**Правило:** минимум 3–4 строки должны заметно отличаться между кейсами. Иначе портфолио выглядит как «одна работа, сделанная три раза».

### SECTION 6 — ДЕНЬ 5: CASE 1 (CORE)

```
Brief → References → Outline → Production → Quality Check → Revision → Final Deliverable → Case Study
```

Приоритет: **FINISH > PERFECT.** Не нужно неделю полировать одну работу — Skill Sprint уже пройден. Но FINISH ≠ плохо: результат обязан пройти Quality Gate из Module 3 (Section 12 того модуля) прежде чем считаться готовым.

### SECTION 7 — ДЕНЬ 6: CASE 2 (DIFFERENT PROBLEM)

CASE 2 решает **другую** бизнес-задачу той же услугой. Аналогии по всем TOP 5 Starter Services:

```
LANDING PAGES:
  CASE 1 — стоматология / салон / детейлинг / мебель (локальный high-intent бизнес)
  CASE 2 — ремонт / строительство / недвижимость / образование (более длинный цикл покупки)
  CASE 3 — premium concept

COMMERCIAL PRESENTATIONS:
  CASE 1 — commercial proposal
  CASE 2 — company / service deck
  CASE 3 — premium pitch / sales presentation

LEAD MAGNETS / PDF GUIDES:
  CASE 1 — короткий checklist (низкий порог, быстрое скачивание)
  CASE 2 — mini guide для эксперта (среднее по объёму, обучающий)
  CASE 3 — premium branded guide (более высокая визуальная проработка)

TELEGRAM CONTENT PACKS:
  CASE 1 — экспертный канал
  CASE 2 — локальный бизнес
  CASE 3 — premium service brand

SHORT-FORM VIDEO SCRIPTS:
  CASE 1 — educational (объясняющий контент)
  CASE 2 — sales / conversion (ведёт к покупке/записи)
  CASE 3 — brand / authority (личный бренд, экспертная позиция)
```

### SECTION 8 — ДЕНЬ 7: CASE 3 + PACKAGING

Первая половина дня — закончить CASE 3. Вторая — упаковать все три работы под одну ссылку (Section 13–14). День 7 **не должен** превращаться в создание большого личного бренда — нужна **MINIMUM PORTFOLIO**, не персональный сайт с 15 разделами.

### SECTION 9 — TOP 5 PORTFOLIO TRACKS

**A · LANDING PAGES**

| | Business type (варианты) | Problem | Deliverable | What it proves |
|---|---|---|---|---|
| Case 1 | Стоматология / салон красоты / детейлинг / мебельная мастерская | Нет страницы, объясняющей услуги и ведущей к записи | Concept-лендинг, 6–8 секций | Базовый коммерческий лендинг |
| Case 2 | Ремонт квартир / стройка / риелтор / онлайн-школа | Длинный цикл принятия решения, нужен расчёт/консультация | Лендинг с формой расчёта/заявки | Адаптация под сложный оффер |
| Case 3 | Premium-ниша по выбору (например premium detailing) | Нужно визуально транслировать уровень «дорого» | Визуально сильный concept-лендинг | Потенциал роста качества |

**B · COMMERCIAL PRESENTATIONS**

| | Тип | Цель | Аудитория | Ориентир слайдов |
|---|---|---|---|---|
| Case 1 | Commercial Proposal | продать услугу/товар B2B | закупщик/владелец бизнеса | 8–12 |
| Case 2 | Company / Service Deck | представить компанию целиком | потенциальный партнёр/клиент | 8–12 |
| Case 3 | Premium Pitch / Sales Deck | закрыть более крупную сделку | инвестор/крупный клиент | 10–14 |

**C · LEAD MAGNETS / PDF GUIDES**

| | Тип | Задача | Deliverable |
|---|---|---|---|
| Case 1 | Checklist | быстрая польза, низкий порог скачивания | 1–2 страницы |
| Case 2 | Mini Guide | обучить одному конкретному навыку/решению | 5–7 страниц |
| Case 3 | Premium Branded Guide | продемонстрировать более высокий уровень оформления | 7–10 страниц с фирменным стилем |

Разница — не только в объёме, а в **задаче**: чек-лист закрывает одно быстрое действие, мини-гайд обучает, premium-гайд продаёт уровень экспертизы через оформление.

**D · TELEGRAM CONTENT PACKS**

| | Тип | Content pillars (пример) | Объём |
|---|---|---|---|
| Case 1 | Экспертный канал | советы / разбор ошибок / кейсы / FAQ | 10 sample posts + календарь |
| Case 2 | Локальный бизнес | услуги / отзывы-заглушки / закулисье / акции | 10 sample posts + календарь |
| Case 3 | Premium service brand | философия бренда / премиальные детали / истории | 10 sample posts + календарь |

**E · SHORT-FORM VIDEO SCRIPTS**

| | Тип | Задача |
|---|---|---|
| Case 1 | Educational | объяснить полезную тему по нише клиента |
| Case 2 | Sales / Conversion | подвести зрителя к записи/покупке |
| Case 3 | Brand / Authority | показать позицию эксперта, личный подход |

Разумный объём кейса: **5–7 сильных сценариев + content angle map** (кратко — какие типы тем/углов подачи покрывает пакет). 10 сценариев на кейс — избыточно для portfolio-цели и раздувает работу без дополнительного доказательства навыка.

### SECTION 10 — PORTFOLIO CASE STUDY FORMAT

```
01 — TITLE                          название проекта
02 — STATUS                         Concept Project
03 — CLIENT TYPE                    например: Premium Dental Clinic
04 — CHALLENGE                      «В рамках концепта я поставил(а) задачу…» — не факт о реальной компании
05 — GOAL                           что должен сделать deliverable
06 — APPROACH                       3–5 ключевых решений
07 — DELIVERABLE                    что создано
08 — KEY DECISIONS                  почему выбраны именно эти решения
09 — FINAL                          основные экраны / слайды / тексты
10 — WHAT THIS CASE DEMONSTRATES    например: information hierarchy, CTA structure, premium visual direction, content strategy
```

**Запрещено поле RESULTS**, если реальных результатов нет. Вместо него — **PROJECT OUTCOME**: результат работы, а не результат бизнеса. Например: «Готовый concept-лендинг из 8 секций» или «10-post Telegram sample pack» — не «+37% заявок».

### SECTION 11 — BAD CASE VS GOOD CASE

| BAD (описание красоты) | GOOD (объяснение решений) |
|---|---|
| «Сделал сайт стоматологии. Красивый современный дизайн.» | «Concept Project для частной стоматологии. Задача концепта — сделать сложный список услуг понятнее и привести пользователя к записи. Поэтому первый экран строится вокруг ключевого направления, далее — врачи, услуги, доверие и CTA.» |
| «Классная презентация для строительной компании.» | «Concept Project — commercial deck для строительной компании. Задача — показать надёжность на длинном цикле сделки, поэтому структура идёт от проблемы клиента к этапам работ и только потом к цене.» |
| «Крутой контент-план для Telegram.» | «Concept-пак для локальной студии красоты. Задача — оживить заброшенный канал, поэтому темы построены вокруг частых вопросов клиентов, а не случайных советов.» |
| «Сделал PDF-гайд, красиво оформлен.» | «Concept-гайд «5 вопросов перед выбором стоматологии». Задача — стать лид-магнитом для клиники: структура ведёт от страха пациента к конкретным критериям выбора и заканчивается CTA на консультацию.» |
| «Написал сценарии для Reels.» | «Concept-пакет из 6 сценариев для мастера маникюра. Задача — закрыть частые возражения аудитории, поэтому каждый сценарий строится на реальном вопросе клиента, а не общей теме.» |

### SECTION 12 — 30-SECOND CASE PITCH

**Формула:**

```
«Это концепт для [TYPE].
Я поставил(а) задачу [PROBLEM].
Сделал(а) [DELIVERABLE].
Главный акцент был на [DECISION].
Работу добавил(а), чтобы показать, как я решаю [TYPE OF TASK].»
```

**1 предложение:** «Это концепт-лендинг для стоматологии, который делает сложный список услуг понятным и ведёт к записи.»

**20–30 секунд (устно/голосовое):** «Это концепт для частной стоматологии. Я поставил(а) задачу — сделать длинный список услуг понятным для человека, который впервые выбирает клинику. Сделал(а) лендинг из 8 секций: сначала ключевое направление, потом врачи, услуги, доверие и запись. Главный акцент был на том, чтобы посетитель за 10 секунд понял, куда он попал и что делать дальше. Я добавил(а) этот кейс, чтобы показать, как я структурирую сложную информацию в понятный путь до записи.»

**Для сообщения клиенту (текст):** «Прикладываю концепт-лендинг для стоматологии — делал(а) его, чтобы показать, как я упаковываю список услуг в понятную страницу с записью. Похожий подход применю и для вашего проекта, с учётом ваших услуг и аудитории.»

### SECTION 13 — PORTFOLIO FORMAT

Не нужен дорогой персональный сайт. MVP-варианты:

```
1. Простая portfolio page
2. PDF portfolio
3. Behance — если услуга визуальная
4. Google Drive / чистая папка — как временный вариант
5. Notion / аналогичная публичная страница — только если это реально ускоряет запуск
```

Клиенту должно быть легко открыть работу. **Плохо:** «Вот ZIP, там 17 файлов.» **Хорошо:** одна ссылка → 3 кейса → понятные превью.

### SECTION 14 — MINIMUM PORTFOLIO PAGE

```
HERO
  [NAME / BRAND]
  [PRIMARY SERVICE]
  короткий оффер

PROJECTS
  CASE 1 · CASE 2 · CASE 3

ABOUT / WORKING STYLE
  2–4 предложения

CONTACT
  Telegram / email / другой канал
```

**Не добавлять:** 15 секций · длинную личную историю · «наша команда», если команды нет · фальшивые логотипы клиентов · фальшивые отзывы · фейковые цифры.

### SECTION 15 — PORTFOLIO TRUST RULES

**Никогда не:** придумывать клиента · придумывать отзыв · придумывать бизнес-результаты · красть чужой кейс · использовать чужой дизайн как свой · показывать AI-output без проверки · вводить клиента в заблуждение относительно опыта.

**Можно:** делать концепты · делать redesign concept · создавать fictional briefs · использовать публичную информацию · показывать процесс · объяснять решения.

### SECTION 16 — AI PORTFOLIO REVIEW

```
Вот описание услуги: [ОПИСАНИЕ УСЛУГИ]
Вот бриф: [BRIEF]
Вот case study: [CASE STUDY]
Вот deliverable: [DELIVERABLE]
Вот мой quality checklist: [CHECKLIST]

Проверь по пунктам: Clarity, Business Logic, Presentation, Consistency,
Obvious Errors, Scope, Credibility, What looks amateur, What should be
improved before showing clients.

Правила: не хвали автоматически. Не придумывай проблемы, которых нет
в материале. Сначала назови 3 самых критичных недостатка — только
потом остальные замечания.
```

### SECTION 17 — HUMAN REVIEW

После AI — обязательна человеческая проверка:

```
☐ открыть работу на телефоне
☐ посмотреть через день свежим взглядом
☐ проверить текст
☐ проверить ссылки
☐ убрать placeholders
☐ убрать AI artifacts (странные повторы, "как AI-модель я...")
☐ убрать придуманные факты
☐ проверить consistency (стиль/тон одинаковы во всех кейсах)
☐ показать одному человеку без контекста
```

Вопрос этому человеку: **«Как ты думаешь, что здесь сделали и для кого?»** Если он не понимает — presentation/упаковка кейса слабые, а не сам концепт.

### SECTION 18 — PORTFOLIO SCORECARD

> Это внутренний инструмент самопроверки, а не объективный рыночный рейтинг.

Шкала 0–2 (0 = нет, 1 = частично, 2 = да):

```
Clear Service                      [ ]
Clear Audience                     [ ]
Clear Problem                      [ ]
Finished Deliverable               [ ]
Visual / Text Quality              [ ]
Business Logic                     [ ]
Case Explanation                   [ ]
No Fake Claims                     [ ]
Easy to View                       [ ]
Consistent Presentation            [ ]
Different From Other Cases         [ ]
Ready to Send                      [ ]

TOTAL: ___ / 24
```

Нет искусственного порога вроде «21/24 гарантирует клиентов». Практическое правило: если много нулей — не отправлять, сначала закрыть очевидные пробелы; если нули единичные — можно отправлять и дорабатывать по ходу.

### SECTION 19 — PORTFOLIO DONE, NOT PERFECT

Симптомы бесконечной полировки: менять шрифт 4 часа · переделывать обложку · искать идеальный mockup · добавлять четвёртый кейс «на всякий случай» · переписывать About в пятый раз.

**Правило:** после Quality Gate (Module 3) и Portfolio Scorecard (Section 18) — **SHIP.** Портфолио улучшится после реальных клиентов; первый настоящий проект ценнее ещё одной недели полировки концептов.

## EXAMPLE

Заполненный Case Study (Track A, Case 1) — см. также Section 11 (GOOD-версия того же кейса):

```
01 TITLE:                     Concept-лендинг для частной стоматологии
02 STATUS:                    Concept Project
03 CLIENT TYPE:                Private Dental Clinic
04 CHALLENGE:                  В рамках концепта я поставил(а) задачу — сделать длинный
                                список услуг понятным для человека, впервые выбирающего клинику
05 GOAL:                       страница должна за 10 секунд объяснить, куда попал посетитель, и вести к записи
06 APPROACH:                   1 ключевое направление на первом экране · врачи · услуги
                                блоками · доверие (сертификаты/гарантии) · один CTA
07 DELIVERABLE:                concept-лендинг, 8 секций, адаптивный макет
08 KEY DECISIONS:              CTA повторяется 3 раза, но не давит; услуги сгруппированы
                                по направлениям, а не одним длинным списком
09 FINAL:                      [превью 8 секций / ссылка на макет]
10 WHAT THIS CASE DEMONSTRATES: information hierarchy, CTA structure, работа со сложным списком услуг
PROJECT OUTCOME:                готовый concept-лендинг из 8 секций
```

# QUALITY CHECK

**1. Может ли новичок создать портфолио без реальных клиентов честно?**
Да: Section 1 явно разводит REAL WORK и CONCEPT WORK, даёт список разрешённых и запрещённых формулировок, а STATUS = Concept Project обязателен в каждой карточке (Section 10).

**2. Достаточно ли отличаются три кейса?**
Да: Case Diversity Matrix (Section 5) требует различий минимум по 3–4 из 8 параметров, а Section 7/9 дают готовые несовпадающие пары ниш/задач по каждой из 5 услуг.

**3. Есть ли конкретные брифы для TOP 5?**
Да: Section 9 — таблицы Business type/Problem/Deliverable/What it proves для всех пяти услуг, плюс Section 3–4 дают универсальный и AI-генератор брифа для любой конкретики внутри них.

**4. Не требует ли система лишней недели работы?**
Нет: Section 6 и 19 прямо задают приоритет FINISH > PERFECT и правило SHIP после Quality Gate/Scorecard; объём кейсов (5–7 сценариев, 8–12 слайдов, 10 постов) зафиксирован, чтобы не раздувать работу.

**5. Учит ли она объяснять бизнес-решения, а не только показывать картинки?**
Да: Section 10 (KEY DECISIONS, WHAT THIS CASE DEMONSTRATES) и Section 11 (BAD vs GOOD) целиком построены на переходе от «красиво» к «почему сделано именно так».

**6. Исключены ли фальшивые результаты и отзывы?**
Да: запрещено поле RESULTS без реальных данных (Section 10), Section 15 — прямой список запретов, Section 4 — явный запрет ИИ выдумывать цифры/факты.

**7. Может ли клиент быстро открыть работы?**
Да: Section 13–14 — правило «одна ссылка → 3 кейса → превью», явный анти-пример «ZIP с 17 файлами».

**8. Есть ли механизм против бесконечной полировки?**
Да: Section 19 (Portfolio Done, Not Perfect) с конкретными симптомами и правилом SHIP.

**9. Готов ли пользователь после Day 7 показать работу реальному бизнесу?**
Да: DONE WHEN заканчивается пунктами «прошёл Portfolio Scorecard» и «готов отправить портфолио потенциальному клиенту» — прямой мост к Module 8 (поиск лидов).

**10. Не дублирует ли Module 4 Skill Sprint?**
Нет: Module 3 учил минимальному навыку и включал одну самостоятельную практическую работу для тренировки; Module 4 не переучивает навык, а превращает уже освоенный процесс в 3 разных, оформленных и упакованных доказательства для клиента — с собственными инструментами (Diversity Matrix, Case Study Format, Scorecard, Pitch), которых в Module 3 не было.
